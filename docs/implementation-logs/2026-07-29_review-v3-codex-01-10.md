### CODEX-01/02 — Checksum numeric-token contract + serialiser (PRs #19, #20)

**Files changed:** `docs/adr/ADR-007-checksum-numeric-token-contract.md` (new),
`cypress/support/books/orderBook.ts`, `scripts/check-checksum-serialization.ts` (later migrated),
`SPECIFICATION.md` (SPEC-004 cross-ref).

`wireNumber()` previously *threw* `ChecksumSerializationError` on any exponent-form token

Structural decisions were captured as ADRs; the table records the rest.

| Decision | Rationale | Alternatives rejected |
|---|---|---|

## Lessons Learned

- **Cross-check the review against repo reality.** Codex named one `brace-expansion` HIGH; a live
  `npm audit` showed **two** HIGH advisories. Reproduce before scoping.
- **An advisory range can force the fix version** — `<=5.0.7` meant only `5.0.8` cleared it; verify a
  forced override is a dual (require/import) package with compatible `engines` before applying it.
- **A Node minimum is a support promise and interacts with the runner** — `node:test` coverage
  enforcement needs Node ≥ 22.8, above the Node 20 floor; run it on the CI baseline and keep
  `test:unit` on the floor rather than silently raising the minimum (ADR-009).
- **Keep the test runner small on a Cypress project** — `node:test` + `tsx` added zero deps and kept
  `audit:ci` at zero; a discovery shim beats shell globs and a glob dependency for portability.
- **Classify environment outcomes; never silence them** — the most-specific product failure must
  outrank a benign environment outcome so a real regression can't hide behind market quiet (ADR-008).
